Methods and Member Functions

How Do Objects Acquire Behavior?

An object combines data with operations that work on that data. In C++, those operations are member functions, also called methods.

Slides 1–9

Member Functions and Methods

  • A method is a function declared as a member of a class.
  • It belongs to the class and is called through an object.
  • Its implementation can work with the object’s private state.

Class Data and Behavior

class Counter {
private:
    int value;
public:
    void increment();
};

The data member stores state; the method defines behavior that operates on that state.

Method Anatomy

return_type ClassName::methodName(parameters) {
    // method body
}

The class name connects an out-of-class definition to its declaration.

Declaring a Method

class Counter {
public:
    void increment();
    int getValue();
};

The declaration tells clients and the compiler which operations the class provides.

Defining a Method Outside the Class

void Counter::increment() {
    value++;
}

int Counter::getValue() {
    return value;
}

The scope-resolution operator identifies the class that owns each method.

Calling a Method

Counter count;
count.increment();
cout << count.getValue();

The object before the dot supplies the state used by the method.

Methods as Forced Abstraction

Methods give clients named operations instead of requiring them to know how the class stores or manipulates its data.

account.deposit(50.00);

The call expresses intent while the implementation remains inside the class.

Methods and Member Functions: Key Ideas

Methods belong to classes, operate on object state, and provide named operations through an interface.

Difference Between Method and Function

Why Distinguish Methods and Functions?

Both are callable blocks of code, but a method belongs to a class and a free function does not. That difference affects state access and design.

Slides 10–16

Ownership of Behavior

double tax(double amount);       // free function
class Invoice {
public:
    double totalWithTax();      // method
};

A method is owned by the class whose object provides the context for the operation.

State Access

A method can use the object’s private members directly. A free function must receive the data it needs through parameters or another explicit interface.

Call Syntax Comparison

total = addTax(amount);          // free function
total = invoice.totalWithTax();  // method

The call syntax reveals whether an object supplies the operation’s state.

Choosing a Method or Function

Use a method when behavior belongs to an object’s state or identity. Use a free function when the operation is independent of a particular object.

Same Behavior, Two Designs

double area(const Rectangle& r);

class Rectangle {
public:
    double area();
};

Both designs can compute area; the method design places the behavior with the data it uses.

Difference Between Method and Function: Key Ideas

The essential distinctions are ownership, access to object state, and call syntax.

Access Specifiers

Why Control Access to Class Members?

Access control determines which code may use or change a class member. It protects state and keeps the public interface intentional.

Slides 17–24

The Three Access Specifiers

  • public members are available to client code.
  • private members are available only inside the class.
  • protected members are available to the class and derived classes.

Access Specifier Anatomy

class Student {
public:
    void print();
private:
    int grade;
};

An access label controls the members that follow it until another label appears.

Public Members

Public methods form the part of the class interface that client code may call.

student.print();

Private Members

Private data and helper methods protect implementation details from direct external access.

// student.grade = 95;  // not allowed outside the class

Default Access in class and struct

class ClassType { int value; };   // private by default
struct StructType { int value; }; // public by default

The default access rule is one practical difference between class and struct.

Choosing an Access Specifier

Keep implementation details private, expose intentional operations publicly, and use protected only when inheritance genuinely needs access.

Access Specifiers: Key Ideas

Access specifiers define the boundary between a class interface and its implementation.

Private Member Functions

Why Hide Helper Methods?

Some operations support the implementation but are not meaningful for clients to call directly. Private member functions keep those helpers out of the public interface.

Slides 25–30

Public Interface and Private Implementation

class Report {
public:
    void print();
private:
    void printHeader();
};

Clients call print; the class may use printHeader internally.

Private Member Function Anatomy

class Report {
private:
    void printHeader();
};

void Report::printHeader() {
    cout << "Report" << endl;
}

The declaration and definition use ordinary method syntax; only the access level changes who may call it.

A Public Method Calling a Private Helper

void Report::print() {
    printHeader();
    cout << "body" << endl;
}

The public operation coordinates private steps without exposing them to clients.

Choosing a Private Helper

Make a method private when clients do not need to call it directly and when exposing it would expand the interface unnecessarily.

Private Member Functions: Key Ideas

Private methods support implementation while keeping the public interface small and purposeful.

Methods as an Interface

Why Does a Class Need an Interface?

Clients need a predictable way to use an object without depending on its internal representation. Public methods provide that boundary.

Slides 31–37

Public Methods as the Interface

The public section describes what an object can do. Clients use those operations without needing to know how the object stores its data.

Interface and Implementation

class BankAccount {
public:
    void deposit(double amount);
private:
    double balance;
};

The public declaration is the interface; the private data and method body are implementation details.

A Method Signature as a Contract

void deposit(double amount);

The return type, name, parameters, and access level communicate the operation a client may request.

Using an Object Through Its Interface

BankAccount account;
account.deposit(100.00);

Client code uses the public method and does not manipulate balance directly.

Changing Implementation Without Changing Clients

The class can change how it stores or computes its state while client calls remain the same. A stable interface reduces the cost of internal changes.

Methods as an Interface: Key Ideas

An interface defines permitted operations while implementation details remain hidden.

Setters and Getters

Why Use Setters and Getters?

Setters and getters provide controlled access to private data instead of exposing data members directly.

Slides 38–45

Setter and Getter Roles

  • A setter updates an object’s state through a named operation.
  • A getter reports an object’s state through a named operation.

Setter Anatomy

void setScore(int newScore) {
    score = newScore;
}

The parameter supplies a candidate value; the method can validate it before assignment.

Getter Anatomy

int getScore() {
    return score;
}

The getter returns state without exposing the data member itself.

A Complete Setter and Getter Example

class Student {
private:
    int grade;
public:
    void setGrade(int value) { grade = value; }
    int getGrade() { return grade; }
};

Direct Access Compared with Methods

Public data allows unrestricted changes. Private data with setters and getters creates a controlled interface that can evolve.

Setter and Getter Contracts

A setter should leave the object in a valid state. A getter should report state without changing it.

Setters and Getters: Key Ideas

Setters control updates and getters control reads through the class interface.

Setters Increase Reliability

Why Should a Setter Reject Data?

If every caller can store any value, an object may enter an invalid state. A setter creates one place to protect that state.

Slides 46–53

Valid State and Invariants

An invariant is a condition that should remain true for a valid object. For example, a grade may need to remain between 0 and 100.

Validation Inside a Setter

void Student::setGrade(int value) {
    if (value >= 0 && value <= 100)
        grade = value;
}

The setter separates accepted input from rejected input.

A Setter That Protects an Object

Student student;
student.setGrade(85);   // accepted
student.setGrade(140);  // rejected

The object remains within its valid range even when a caller supplies bad data.

Before and After Validation

Before the call, the object has a valid grade. After an invalid call, the setter retains the previous valid value rather than corrupting the object.

Boundary Values and Invalid Input

For a grade from 0 through 100, test 0, 100, -1, and 101. Boundary tests reveal whether the condition includes the correct limits.

Choosing a Rejection Policy

A setter may retain the old value, assign a safe default, or report an error. The policy should be explicit and consistent with the class contract.

Setters Increase Reliability: Key Ideas

Setters centralize validation and help keep objects in a valid state.

Getters

How Can Clients Observe Object State?

Clients often need to read an object’s state without changing it. A getter provides that controlled observation.

Slides 54–60

The Role of a Getter

A getter is a method that reports a value from an object without changing the object’s state.

Getter Anatomy

int Student::getGrade() {
    return grade;
}

The return type describes the reported value, and the returned member remains private.

A Getter in a Complete Class

Student student;
student.setGrade(92);
cout << student.getGrade() << endl;

Client code receives the value through the interface.

Getter Calls Do Not Change State

Calling a getter repeatedly should report the same state unless another operation changes the object.

Returning a Value Through the Interface

Returning a value gives the caller a result without granting direct access to the data member. The class retains control of its representation.

Getters: Key Ideas

Getters provide controlled observation while preserving encapsulation.
