Functors

Why Pass Behavior as Data?

A program can pass values into a function. Can it also pass the action that should be performed? This topic answers that question with function objects.

Slides 5–22

A Function Pointer Already Passes Behavior

A function pointer lets one function receive another function’s address. The receiving function can decide when to invoke the behavior.

#include <iostream>
using namespace std;

void printValue(int value);
void applyOnce(int value, void (*action)(int));

int main() {
    applyOnce(42, printValue);
    return 0;
}

void printValue(int value) {
    cout << value << '\n';
}

void applyOnce(int value, void (*action)(int)) {
    action(value);
}

A Functor Is a Callable Object

A functor is an object whose class overloads operator(). The object carries behavior and can be passed where a callable is expected.

A Complete Functor Program

#include <iostream>
using namespace std;

// A functor that prints one value
class PrintValue {
public:
    void operator()(int value) const;
};

int main() {
    PrintValue printer;

    // Call the object as if it were a function
    printer(42);
    printer(7);

    return 0;
}

void PrintValue::operator()(int value) const {
    cout << "Value: " << value << '\n';
}
Value: 42
Value: 7

This is the whole pattern in one runnable program. The slides that follow take it apart piece by piece.

Functor Anatomy

A functor’s class overloads operator(), the function-call operator, just as other classes overload operator+ or operator[]. Calling the object with parentheses runs operator().

class PrintValue {                       // an ordinary class
public:
    void operator()(int value) const {   // the function-call operator
        cout << value << '\n';
    }
};

PrintValue printer;   // create the object
printer(42);          // call the object, which runs operator()

The Call Contract

The functor’s operator() signature tells the caller what each invocation accepts and returns. A clear contract makes the object usable by other code.

class IsPositive {
public:
    bool operator()(int value) const {
        return value > 0;
    }
};

Pass the Object to Another Function

The receiving function decides when to call the functor; the functor decides what the call does. Because the parameter type is IsPositive, this version accepts only that one functor. Topic 2 shows how for_each accepts any callable.

void reportIfPositive(int value, const IsPositive& test) {
    if (test(value)) {
        cout << value << " is positive\n";
    }
}

One Object Can Be Called Repeatedly

The same functor object can be invoked for many values. The receiving algorithm controls the repetition while the functor controls the behavior.

PrintValue printer;
printer(10);
printer(20);
printer(30);

A Stateless Functor

A stateless functor contains no changing data. It is useful when the behavior is reusable but does not need to remember previous calls.

class DoubleValue {
public:
    void operator()(int& value) const {
        value *= 2;
    }
};

Predicates Ask Yes-or-No Questions

A predicate is a callable that returns true or false. Predicate functors let an algorithm ask a question without owning the question’s implementation.

class IsEven {
public:
    bool operator()(int value) const {
        return value % 2 == 0;
    }
};

IsEven isEven;
cout << boolalpha << isEven(10) << ' ' << isEven(7) << '\n';   // prints true false

Predicate Invariant

For the same unchanged input, a simple predicate should answer the same question every time. Its parameter and return type form a contract with the algorithm using it.

IsEven isEven;
cout << boolalpha << isEven(10) << ' ' << isEven(10) << '\n';   // true true

// Breaks the invariant: the answer depends on how many calls came before
class EveryOther {
private:
    int calls = 0;

public:
    bool operator()(int value) {
        calls++;
        return calls % 2 == 0;
    }
};

EveryOther flaky;
cout << flaky(10) << ' ' << flaky(10) << '\n';                  // false true

An algorithm may call a predicate more than once on the same element, or call a copy of it. A predicate whose answer changes between calls gives unpredictable results.

Stateful Functors Store a Policy

A functor can store data that controls its behavior. The object then packages both the policy and the operation that applies it.

class AddToTotal {
private:
    int total = 0;

public:
    void operator()(int value) {
        total += value;
    }

    int result() const {
        return total;
    }
};

Stateful Functor Demonstration

The object remembers information between calls because its state belongs to the object.

AddToTotal total;
total(4);
total(7);
cout << total.result() << '\n';

Trace the Object State

Statement total before total after

total(4); 0 4

The state lives inside the object, so each call starts from the value the previous call left behind.

Why Use a Functor?

A functor keeps the behavior close to its state, gives the behavior a type, and can be passed to reusable algorithms. It is useful when a plain function does not have enough context.

Validate Input Length with a Functor

The constructor sets the number of characters the functor will count to. Each call takes the actual string, counts its characters, and answers whether the input is valid.

#include <iostream>
#include <string>
using namespace std;

// A functor that checks whether input fits within a character limit
class MaxLength {
private:
    int limit;

public:
    MaxLength(int maxCharacters);
    bool operator()(const string& input) const;
};

int main() {
    // The constructor sets how many characters are allowed
    MaxLength validUsername(8);

    string names[] = {"ada", "grace_hopper", "linus"};
    for (const auto& name : names) {
        if (validUsername(name)) {
            cout << name << ": accepted\n";
        } else {
            cout << name << ": too long\n";
        }
    }

    return 0;
}

MaxLength::MaxLength(int maxCharacters) : limit(maxCharacters) {}

// Count the characters, stopping as soon as the count passes the limit
bool MaxLength::operator()(const string& input) const {
    int count = 0;
    for (size_t i = 0; i < input.length(); i++) {
        count++;
        if (count > limit) {
            return false;
        }
    }
    return true;
}
ada: accepted
grace_hopper: too long
linus: accepted

The policy, eight characters, is set once when the object is created. The same object then validates every name. A different limit is a different object: MaxLength validPassword(16).

Common Practices

  • Give operator() a narrow, clearly named responsibility.
  • Keep stored state minimal and expose only the results the caller needs.
  • Make operator() const when invoking it should not change the object.

Summary

A functor is an object that packages callable behavior. Its operator() defines the call contract, and its state can preserve information across repeated invocations.

Range-Based Loops and std::for_each

Why Have Two Looping Tools?

A range-based for loop makes direct traversal readable. std::for_each separates traversal from the action applied to each element.

Slides 24–41

Range-Based Loop Anatomy

A range-based loop names an element variable and a range. The loop obtains each element without requiring an index.

for (auto& value : values) {
    value *= 2;
}

Choose the Element Reference Carefully

auto makes a copy, auto& permits modification of the original element, and const auto& avoids copying while preventing modification.

vector<int> values = {1, 2, 3};

for (auto value : values) {
    value *= 10;            // changes a copy
}
for (const auto& value : values) {
    cout << value << ' ';   // reads without copying
}
cout << '\n';

for (auto& value : values) {
    value *= 10;            // changes the original
}
for (const auto& value : values) {
    cout << value << ' ';
}
cout << '\n';
1 2 3
10 20 30

A Range Has a Boundary

A vector knows its size, so a range-based loop can discover where to stop. A built-in array also knows its size, until it is passed to a function and becomes a pointer.

A Pointer Is Not a Complete Range

When an array is passed as a pointer, the size is no longer part of the pointer value. An algorithm needs both a first position and a one-past-the-end position.

int values[] = {1, 2, 3, 4};
int* first = values;
int* last = values + 4;

std::for_each Separates Traversal and Action

std::for_each walks through an iterator range and invokes a callable for each element. The algorithm owns the traversal; the callable owns the action.

std::for_each Anatomy

The call supplies a beginning position, an ending position, and an object that can be called with one element. for_each is declared in the algorithm header.

#include <algorithm>

for_each(first, last, action);

Use a Named Functor with for_each

A named functor gives for_each the behavior it should apply to each element. begin(values) and end(values) supply the first and one-past-the-end positions, so the size is never typed by hand.

class DoubleValue {
public:
    void operator()(int& value) const {
        value *= 2;
    }
};

int values[] = {1, 2, 3, 4};
for_each(begin(values), end(values), DoubleValue());

DoubleValue() is an anonymous object: a temporary DoubleValue with no name, as in 06.01. It exists only for this call.

Predict the Total After for_each

AddToTotal adds every value it receives to its own total. What does this print?

Let students commit to an answer before advancing. Most will say 10.

for_each Works on a Copy of the Functor

It prints 0. for_each takes the functor by value, so it adds 1, 2, 3, and 4 to its own copy of total. The original object is never touched, and the updated copy is returned and thrown away.

Store the copy that for_each returns to see the result.

total = for_each(begin(values), end(values), total);
cout << total.result() << '\n';   // prints 10

[Graphic suggestion: two boxes labeled total and copy. The copy box fills to 10 while for_each runs; total stays at 0.]

Pass a Fresh Anonymous Object

The usual way to write this call skips the named object. AddToTotal() creates an anonymous object, a temporary with no name, and for_each returns its updated copy.

AddToTotal result = for_each(begin(values), end(values), AddToTotal());
cout << result.result() << '\n';   // prints 10

Because for_each works on a copy anyway, a named original only adds a variable that never changes. Name the object only when the code must use it again before or after the call.

Students saw anonymous objects in 06.01. The same idiom appears with DoubleValue(), PrintValue(), and CountAtLeast(70); constructor arguments still configure an anonymous object.

Range-Based for and for_each

Both forms visit each element in a range. The range-based loop keeps the action in the loop body; for_each makes the action an object that can be named, passed, and reused.

When Should You Choose Each One?

Use a range-based for when the action is local, simple, and clear in the loop body. Use for_each when the action is an independent policy that should be named, passed to another function, reused, or paired with stored state.

Count Matching Values in a vector

The same pattern works on a vector, and the functor can answer a question about the data instead of changing it.

class CountAtLeast {
private:
    int threshold;
    int count = 0;

public:
    CountAtLeast(int limit) : threshold(limit) {}

    void operator()(int value) {
        if (value >= threshold) {
            count++;
        }
    }

    int result() const {
        return count;
    }
};

vector<int> scores = {72, 95, 58, 88};
CountAtLeast passing =
    for_each(scores.begin(), scores.end(), CountAtLeast(70));
cout << passing.result() << '\n';
3

Apply the Pattern to a Raw Pointer Range

For a raw dynamic array, the caller must preserve the range boundary. The callable can remain independent of how the memory was allocated.

int* first = scores;
int* last = scores + size;
for_each(first, last, PrintValue());

The Shared Model

The loop form changes, but the responsibility split stays the same: one component traverses the range and another component defines what happens to each element.

Summary

A range-based for is direct and local. std::for_each makes the action a reusable callable, which allows functors to carry policy and state through an algorithm.

Invariants and Assertions

Where Did This Bug Start?

A program crashes inside a print function, but the print function is correct. The real mistake happened earlier, when a counter quietly moved past its limit. This topic shows how to make a program stop at the cause instead of the symptom.

Slides 49–71

Open with a short story: the crash appears far from the line that broke the data. Students should leave able to explain why invariants and assertions shorten that distance.

You Already Reason About Conditions

A loop condition decides whether another iteration is safe. A range boundary tells an algorithm where to stop. A functor’s call contract tells the caller what each invocation accepts and returns.

Connect to Topics 1 and 2. Students have already relied on conditions that must be true for code to work; today those conditions become explicit and checkable.

An Invariant Is a Condition That Must Hold

An invariant is a condition that must be true at a specific point in a program every time execution reaches that point. When an invariant is false, the program’s data is no longer valid.

  • A sorted array stays sorted after an insert.
  • A stack’s count stays between 0 and its capacity.
  • A fraction’s denominator is never 0.

Where Conditions Live

  • Preconditions
  • Postconditions
  • Class invariants
  • Loop invariants

Preconditions and Postconditions

A precondition is what the caller must guarantee before a call. A postcondition is what the function guarantees when it returns.

// Precondition: size > 0
// Postcondition: returns the largest element of values
int findMax(const int values[], int size);

[Graphic suggestion: a function drawn as a box, with the precondition on the arrow going in and the postcondition on the arrow coming out. Label the caller’s side and the function’s side to show who is responsible for each.]

Class Invariants

A class invariant is a condition every object of the class keeps whenever outside code can see it. In BoundedStack, count is both the number of stored values and the index of the next open slot, so it must stay between 0 and CAPACITY. A push on a full stack would write past the end of items and leave count at 4.

// Class invariant: 0 <= count <= CAPACITY
class BoundedStack {
private:
    int items[CAPACITY];
    int count = 0;

public:
    void push(int value);
    int pop();
    int size() const;
};
void BoundedStack::push(int value) {
    // Invariant holds on entry
    items[count] = value;
    count++;
    // Invariant must hold again on exit
}

The initializer count = 0 establishes the invariant when the object is created. Every public member function may assume it on entry and must restore it before returning. Inside the function, between those two points, it may be briefly false.

This push still has a hole: nothing stops a fourth call on a full stack. Slide 58 closes that hole with an assertion.

[Graphic suggestion: the items array drawn as three boxes with count as an arrow pointing at the next open slot, shown at counts 0 through 3.]

Encapsulation Protects the Invariant

If count is public, any code anywhere can set it to 50 and break the invariant. If count is private, only the member functions can change it, so only they need to be checked.

This is the design payoff of private data. Encapsulation shrinks the number of places a bug can come from, which makes troubleshooting faster.

Loop Invariants

A loop invariant is true at the top of every iteration. When the loop ends, the invariant plus the exit condition tells you the result.

int maxValue = values[0];
for (int i = 1; i < size; i++) {
    // Invariant: maxValue is the largest of values[0] through values[i - 1]
    if (values[i] > maxValue) {
        maxValue = values[i];
    }
}

assert Anatomy

assert evaluates an expression at run time. If the expression is false, it prints the expression, file, and line, then stops the program with abort().

#include <cassert>

assert(count < CAPACITY);
//     ^ condition that must be true here

An Assertion Catches the Cause

int main() {
    BoundedStack stack;

    stack.push(10);
    stack.push(20);
    stack.push(30);
    // size() returns count, which is 3 after three pushes
    cout << "Size: " << stack.size() << '\n';

    // This call violates the precondition of push
    stack.push(40);
    cout << "This line never prints\n";

    return 0;
}

void BoundedStack::push(int value) {
    // Precondition: check before writing, while count is the next open slot
    assert(count < CAPACITY && "push on a full stack");
    items[count] = value;
    count++;
    // After the change, confirm 0 <= count <= CAPACITY
    checkInvariant();
}

int BoundedStack::size() const {
    // The size of the stack is the value of count
    return count;
}

Full program: cpp/invariant_stack.cpp. CAPACITY is 3, so the fourth push finds count equal to 3 and the assertion fails before items[3] is written.

The assertion comes before the increment on purpose. A precondition is checked before the operation, while count still names the slot about to be written. Checking after count++ would be too late: the out-of-bounds write would already have happened, and the test would also reject the legal third push, where count becomes 3. The check after the change is checkInvariant(), which uses <= instead of <.

The output shown is the macOS clang format. g++ on Linux prints the same information in a different order. Without the assertion, the fourth push writes past the end of items and the program fails later, somewhere unrelated.

Check the Invariant After Every Change

Write the class invariant once in a private checkInvariant() member function. Call it at the end of every member function that changes the object.

void BoundedStack::checkInvariant() const {
    assert(count >= 0 && count <= CAPACITY && "count is out of range");
}

int BoundedStack::pop() {
    assert(count > 0 && "pop on an empty stack");
    count--;
    checkInvariant();
    return items[count];
}

Make the Failure Message Informative

A string literal is always true, so adding it with && does not change the test. It does put a readable explanation into the failure message.

assert(denominator != 0 && "Fraction denominator must not be zero");

NDEBUG Removes Assertions

When the macro NDEBUG is defined, every assert expands to nothing. Release builds commonly define it, so assertions cost nothing in the shipped program.

// Defined on the command line: g++ -DNDEBUG main.cpp
// or in code, before the include:
#define NDEBUG
#include <cassert>

Debug Build or Release Build?

What does this print in a debug build? What does it print when NDEBUG is defined?

int attempts = 0;
assert(++attempts == 1);
cout << attempts << '\n';

The debug build prints 1. The release build prints 0, because the increment disappears with the assertion.

Let students commit to an answer before advancing. The lesson: an assertion should only test state, never change it.

static_assert Checks at Compile Time

assert checks a condition while the program runs. static_assert checks a constant condition while the program compiles, so a violation never produces an executable.

const int CAPACITY = 3;

static_assert(CAPACITY > 0, "CAPACITY must be positive");
static_assert(sizeof(int) >= 4, "int must be at least 32 bits");

Use it to guard assumptions that are already fixed when the program is built, such as a constant’s value or the size of a type. If someone later sets CAPACITY to 0 or builds on a platform with a 16-bit int, the build fails with your message instead of the program misbehaving. It costs nothing at run time, and NDEBUG cannot turn it off.

Assertions or Error Handling?

assert Exception or error code
Purpose Catch programmer errors Handle expected failures
Example count exceeds capacity user types a negative age
Release build Removed by NDEBUG Still runs
Response Stop and fix the code Recover or report to the user

Rule of thumb: if a correct program could still reach this condition, it is not an assertion. Bad input and missing files are normal events; a full stack being pushed is a bug.

Fail Fast Turns a Symptom into a Cause

Without the check, bad data travels until something unrelated crashes. With the check, the program stops at the exact line where the invariant broke, and the debugger’s call stack points at the caller who broke it.

Return to the opening story from Slide 49. The assertion moved the crash from the print function back to the push that caused it.

[Graphic suggestion: two timelines side by side. Without an assertion, a long gap separates the bad write from the crash. With an assertion, the two points coincide.]

Contracts in C++26

C++26 adds contract assertions that place preconditions and postconditions in the function declaration. The idea is the same as assert; the condition becomes part of the function’s interface.

int findMax(const int values[], int size)
    pre(size > 0);

void push(int value)
    pre(count < CAPACITY)
    post(count <= CAPACITY);

contract_assert(count >= 0);

Forward-looking only. Compiler support is still arriving, so students should keep using assert and static_assert in this course.

Contract Evaluation Semantics

Every contract check runs under one of four evaluation semantics. The choice is made per build, usually with a compiler flag, not with NDEBUG.

  • ignore: the condition is not checked.
  • observe: a failed check calls a violation handler, then the program continues.
  • enforce: a failed check calls a violation handler, then the program terminates.
  • quick_enforce: a failed check terminates the program immediately.

The default semantic is implementation-defined, and an implementation may apply different semantics to different checks in the same program.

Contracts Versus assert

assert Contract assertions
Turned off by NDEBUG The ignore semantic
Choices On or off ignore, observe, enforce, quick_enforce
On failure Print a message and abort Call a replaceable violation handler
Keep running after a failure No Yes, under observe

The observe semantic has no assert equivalent. It lets a production build record violations without crashing, which is useful when a failure must be reported but stopping the program would do more harm.

Contract Support Is Still Evolving

Contracts are part of C++26, but compiler support is still arriving and flag names differ between compilers. In this course, use assert and static_assert.

A contract condition may be evaluated once, more than once, or not at all. Like an assert expression, it should test state and never change it.

Check your compiler’s documentation before demonstrating a specific flag.

Common Practices

  • Write the invariant in a comment first, then enforce it in code.
  • Check preconditions at the start of public member functions.
  • Call checkInvariant() at the end of every member function that changes the object.
  • Use assertions for programmer errors and exceptions or error codes for expected failures.

Summary

An invariant is a condition that must always hold, and an assertion makes the program stop the moment it does not. Stopping at the cause, not the symptom, is what turns invariants into a troubleshooting tool.

Can Assertions Find the Bugs for You?
