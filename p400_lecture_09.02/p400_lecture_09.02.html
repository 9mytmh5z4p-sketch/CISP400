Functor Review

What Did a Functor Give Us?

A functor is an object whose class overloads operator(), so calling the object runs code. That let us hand behavior to for_each the same way we hand it data. What did that convenience cost?

Slides 5–10

Keep this review brisk. Every idea here was covered in 09.01; the point is to reload the model and expose its cost before lambdas arrive.

Functor Anatomy in Brief

class AddToTotal {                 // an ordinary named class
private:
    int total = 0;                 // state the object keeps between calls

public:
    void operator()(int value) {   // the function-call operator
        total += value;
    }

    int result() const {
        return total;
    }
};

AddToTotal total;                  // create the object
total(4);                          // call the object, which runs operator()

Point at the total member. In topic 3, a lambda capture plays exactly this role: it is the state the callable carries with it.

Predicates Answer Yes or No

A predicate is a callable that returns true or false. An algorithm can ask the question without knowing how it is answered.

class IsPositive {
public:
    bool operator()(int value) const {
        return value > 0;
    }
};

IsPositive isPositive;
cout << boolalpha << isPositive(5) << ' ' << isPositive(-3) << '\n';   // prints true false

Topic 4 hands predicates like this one to count_if and find_if.

What Does total Hold?

What does this program print?

int values[] = {1, 2, 3, 4};
AddToTotal total;

for_each(begin(values), end(values), total);

cout << total.result() << '\n';

Answer: 0. for_each receives a copy of total, adds 1 through 4 to the copy, and returns it. The original total never changes. A lambda that captures by value makes this same mistake in topic 3, so let students state the cause in their own words before moving on.

The Class Is Bigger Than the Work

class AddToTotal {
private:
    int total = 0;

public:
    void operator()(int value) {
        total += value;
    }

    int result() const {
        return total;
    }
};

One line does the work. The rest is a class definition written somewhere other than the for_each call that uses it. What if the behavior could be written right where it is needed?

Let the closing question hang. Topic 2 answers it.

Summary

A functor packages behavior and state as an object, but even one line of logic needs a named class.

Lambda Expressions

Can We Write the Behavior Where It Is Used?

The functor review ended with a question: what if the behavior could be written right where it is needed? C++ answers it with the lambda expression.

Slides 12–21

Functor and Lambda Side by Side

class DoubleValue {
public:
    void operator()(int& value) const {
        value *= 2;
    }
};

for_each(begin(values), end(values),
         DoubleValue());
for_each(begin(values), end(values),
         [](int& value) { value *= 2; });

Same behavior and same call. The lambda needs no class, and the behavior sits where for_each uses it.

DoubleValue is the stateless functor from 09.01. Ask students what disappeared and what stayed the same: the parameter and the body survive unchanged.

A Lambda Is a Functor Without the Class

A lambda expression creates an unnamed callable object in the middle of other code. The compiler writes the class and its operator() for you. The object a lambda expression creates is called a closure.

Lambda Anatomy

[]               // capture list
(int& value)     // parameter list
-> void          // return type
{ value *= 2; }  // body
  • Capture list: names outside variables the lambda may use.
  • Parameter list: works exactly like a function’s parameter list.
  • Return type: optional; the compiler usually works it out.
  • Body: the code that runs each time the lambda is called.

The capture list stays empty until topic 3. When a lambda takes no parameters, the empty parentheses may be left out: [] { … } is legal. This layout, one part per line, is legal C++, but nobody writes lambdas this way; it is spread out here only for labeling.

A Complete Lambda Program

#include <iostream>
#include <algorithm>
using namespace std;

int main() {
    int values[] = {1, 2, 3, 4};

    // Store a lambda in a variable
    auto doubleIt = [](int& value) { value *= 2; };

    // Call it directly
    int single = 5;
    doubleIt(single);
    cout << "single: " << single << '\n';

    // Pass the same lambda to for_each
    for_each(begin(values), end(values), doubleIt);

    for (int value : values) {
        cout << value << ' ';
    }
    cout << '\n';

    return 0;
}
single: 10
2 4 6 8

Calling a lambda looks exactly like calling a function or a functor. The same object can be called directly and handed to an algorithm.

What the Compiler Writes for You

auto doubleIt =
    [](int& value) { value *= 2; };
class __Lambda_1 {   // name chosen by the compiler
public:
    void operator()(int& value) const {
        value *= 2;
    }
};

auto doubleIt = __Lambda_1();

Every lambda gets its own class with a name only the compiler knows. That is why the variable is declared with auto: there is no type name you could write.

This is a model, not literal code; the real class name is chosen by the compiler and differs between compilers. Point out that the generated operator() is const by default. Topic 3 needs that detail to explain mutable.

What Does This Print?

#include <iostream>
using namespace std;

int main() {
    auto greet = []() { cout << "Hello from the lambda\n"; };

    cout << "Done\n";
    return 0;
}

Answer: only “Done”. Defining a lambda creates the object; the body runs only when the object is called with greet(). It is the same as creating a functor object and never calling it. With -Wall, g++ even warns that greet is set but not used.

When the Return Type Must Be Stated

The compiler deduces the return type from the return statements. When they disagree, compilation stops.

auto average = [](int sum, int count) {
    if (count == 0) {
        return 0;
    }
    return sum / static_cast<double>(count);
};
// error: inconsistent types 'int' and
// 'double' deduced for lambda return type
auto average = [](int sum, int count) -> double {
    if (count == 0) {
        return 0;
    }
    return sum / static_cast<double>(count);
};
// compiles: return 0 converts to 0.0

The first return yields int and the second yields double, so deduction fails. Stating -> double gives the compiler one type and converts the first return to match.

Functor or Lambda?

  • Lambda: short behavior used in one place, especially as an algorithm argument.
  • Named function: reusable behavior that keeps no state between calls.
  • Functor: reusable behavior with state, or behavior other code must refer to by type name.

If a lambda grows past a few lines, give the behavior a name.

Students often ask how to write their own function that accepts a lambda. The full answer needs templates or std::function, both covered in a later lecture. For now, store lambdas with auto and pass them to standard algorithms.

Summary

A lambda is a functor the compiler writes for you, defined where it is used. Leave the return type off unless the compiler cannot work it out.

Captures and Closures

Why Won’t This Compile?

This lambda tries to do AddToTotal’s job with a local variable instead of a class.

int values[] = {1, 2, 3, 4};
int total = 0;

for_each(begin(values), end(values),
         [](int value) { total += value; });
// error: 'total' is not captured

Slides 23–35

Let students guess before revealing the error. A lambda body cannot see the local variables around it unless the capture list hands them over. The empty brackets from topic 2 are the reason.

What a Capture Does

The capture list names the outside variables a lambda may use. The closure, the object created when the lambda expression runs, carries those variables with it.

Global and static variables are visible without a capture, which is why cout never appears in a capture list. Captures are only needed for local variables.

Capture Forms

Capture Meaning
[] Nothing
[x] x by value
[&x] x by reference
[=] Every variable the body uses, by value
[&] Every variable the body uses, by reference
[=, &x] By value, except x by reference
[&, x] By reference, except x by value
[this] The current object, through its pointer

Students often assume [=] copies everything in scope. It captures only the variables the body actually uses.

Captures Become Member Variables

int bonus = 5;
int total = 0;

auto addBonus =
    [bonus](int x) { return x + bonus; };

auto addToTotal =
    [&total](int x) { total += x; };
class __Lambda_2 {
private:
    int bonus;    // a copy
public:
    __Lambda_2(int b) : bonus(b) {}
    int operator()(int x) const {
        return x + bonus;
    }
};

class __Lambda_3 {
private:
    int& total;   // a reference to the original
public:
    __Lambda_3(int& t) : total(t) {}
    void operator()(int x) const {
        total += x;
    }
};

The constructor runs when the lambda expression runs, so captured values are fixed at creation, not at the call.

This extends the model from slide 17. Note that addToTotal’s operator() is still const, yet total += x compiles: const protects the closure’s own members, and a reference member is never reseated. The variable it refers to belongs to main.

Capturing this in a Member Function

#include <iostream>
#include <algorithm>
using namespace std;

// Applies a fixed curve to an array of scores
class Gradebook {
private:
    int curve;

public:
    Gradebook(int points);
    void applyCurve(int scores[], int size) const;
};

int main() {
    Gradebook gradebook(5);
    int scores[] = {70, 82, 91};

    gradebook.applyCurve(scores, 3);

    for (int score : scores) {
        cout << score << ' ';
    }
    cout << '\n';

    return 0;
}

Gradebook::Gradebook(int points) : curve(points) {}

void Gradebook::applyCurve(int scores[], int size) const {
    // [this] lets the lambda reach the object's members
    for_each(scores, scores + size,
             [this](int& score) { score += curve; });
}
75 87 96

Inside a member function, curve really means this->curve, as in 07.01. A data member is not a local variable, so it cannot be captured by name; capturing this gives the closure the object’s pointer, and the lambda reaches curve through it.

When Is the Copy Made?

What does this print?

int bonus = 5;
auto addBonus = [bonus](int x) { return x + bonus; };

bonus = 100;
cout << addBonus(1) << '\n';

Answer: 6. The closure copied bonus when the lambda expression ran, while bonus was still 5. Changing bonus afterward does not reach the copy.

Value Versus Reference

int bonus = 5;
auto addBonus =
    [bonus](int x) { return x + bonus; };
bonus = 100;
cout << addBonus(1) << '\n';   // 6
int bonus = 5;
auto addBonus =
    [&bonus](int x) { return x + bonus; };
bonus = 100;
cout << addBonus(1) << '\n';   // 101
[bonus] [&bonus]
Closure holds A copy of 5 A reference to bonus
bonus after assignment 100 100
addBonus(1) 6 101

Fixing the Total

int values[] = {1, 2, 3, 4};
int total = 0;

for_each(begin(values), end(values),
         [&total](int value) { total += value; });

cout << total << '\n';   // prints 10

The functor version on slide 8 printed 0. Capturing total by reference lets the closure update the original.

for_each still copies the closure, exactly as it copied AddToTotal. The difference is what gets copied: a reference member. The copy refers to the same total in main, so every addition lands in the original.

By-Value Captures Are Read-Only

int count = 0;

auto bad = [count]() { count++; };
// error: increment of read-only variable 'count'

auto tick = [count]() mutable { return ++count; };
// compiles: changes the closure's own copy

A by-value capture never changes the original variable, with or without mutable.

The generated operator() is const, as noted on slide 17, so a by-value capture cannot be modified. mutable removes that const. It does not turn the capture into a reference; the original count is untouched.

Trace a mutable Closure

int count = 0;
auto tick = [count]() mutable {
    return ++count;
};

cout << tick() << ' ';
cout << tick() << ' ';
cout << tick() << '\n';
cout << count << '\n';
Statement Closure’s count main’s count Prints
auto tick = … 0 0
tick() 1 0 1
tick() 2 0 2
tick() 3 0 3
cout << count 3 0 0

Output: 1 2 3 on the first line and 0 on the second. The closure remembers its count between calls, just like a stateful functor, while main’s count never moves.

Who Owns the Captured Data?

Capture Closure holds Safe to call
[x] Its own copy Any time
[&x] A reference to x Only while x exists
[this] A copy of the object’s pointer Only while the object exists

A by-value closure owns its data. A by-reference closure borrows it.

[this] copies the pointer, not the object, so it carries the same lifetime risk as a reference capture. Before C++20, [=] also captured this silently; that implicit capture is now deprecated, so write [this] explicitly. A code example of a dangling reference capture is in the appendix.

Value or Reference?

  • Capture by reference when the lambda must update the caller’s variable, or the data is large and the lambda runs immediately.
  • Capture by value when the lambda only reads a small value, or might run after the variable is gone.
  • Name each capture instead of using [=] or [&], so the capture list documents what the lambda depends on.

Summary

A capture becomes a member of the closure: a copy when captured by value, a reference when captured by reference. Reference captures, including this, must not outlive what they refer to.

Lambdas with STL Algorithms

Where Do Lambdas Earn Their Keep?

The standard algorithms already know how to walk a range. What they cannot know is which question to ask about each element or what order you want. A lambda supplies that missing piece right at the call.

Slides 37–48

Algorithms That Take a Lambda

Algorithm What the lambda supplies
for_each The action to perform on each element
count_if The yes-or-no question to count
find_if The yes-or-no question to search for
sort The ordering rule

All four come from . begin and end are officially declared in ; often pulls them in, but include so the code compiles everywhere. Many other algorithms, such as any_of and all_of, follow the same pattern; examples are in the appendix.

count_if Asks a Predicate

int scores[] = {88, 64, 92, 71, 55};

int passed = count_if(begin(scores), end(scores),
                      [](int score) { return score >= 70; });

cout << passed << '\n';   // prints 3

count_if calls the predicate once per element and counts the true answers.

This is the predicate idea from slide 7, now written as a lambda at the call site instead of as an IsPositive-style class.

Capture the Threshold

int passing = 70;

int passed = count_if(begin(scores), end(scores),
                      [passing](int score) { return score >= passing; });

The passing score now lives in one variable. Change it, and the same lambda counts against the new threshold.

Capture by value is the right choice here: the lambda only reads passing and runs immediately. This is topic 3’s decision rule applied to a real algorithm.

find_if Returns a Position

int scores[] = {88, 64, 92, 71, 55};

int* firstFail = find_if(begin(scores), end(scores),
                         [](int score) { return score < 70; });

if (firstFail != end(scores)) {
    cout << "First failing score: " << *firstFail << '\n';   // 64
}

find_if returns a pointer to the first matching element. When nothing matches, it returns end(scores), the one-past-the-end position, so check before dereferencing.

For an array, the position is a plain pointer, which is why int* works here. Containers such as vector return an iterator instead, which acts like a pointer; auto works for both. Iterators are covered properly in the STL lectures.

What Does This Print?

int scores[] = {88, 92, 71, 95};

int* firstFail = find_if(begin(scores), end(scores),
                         [](int score) { return score < 70; });

if (firstFail != end(scores)) {
    cout << "First failing score: " << *firstFail << '\n';
} else {
    cout << "Everyone passed\n";
}

Answer: Everyone passed. No score is below 70, so find_if returns end(scores). Without the check, *firstFail would read one past the end of the array, which is undefined behavior. The appendix shows that mistake in full.

sort with a Comparator

int scores[] = {88, 64, 92, 71, 55};

sort(begin(scores), end(scores));

sort(begin(scores), end(scores),
     [](int a, int b) { return a > b; });
Contents
Before 88 64 92 71 55
After sort with no comparator 55 64 71 88 92
After sort with a > b 92 88 71 64 55

The comparator answers one question: should a come before b?

The Comparator Rule

When a and b are equal, neither should come before the other, so the comparator must return false.

[](int a, int b) { return a > b; }    // false when a == b
[](int a, int b) { return a >= b; }   // true when a == b: breaks sort

Use < or >, never <= or >=.

sort assumes a strict ordering. A comparator that answers true for equal elements is undefined behavior: the result may be misordered, and with many equal values the program can crash. This is the same principle as the predicate invariant from 09.01: the algorithm relies on the callable answering consistently.

Sorting Objects by a Member

class Student {
private:
    string name;
    int score;

public:
    Student(string studentName, int studentScore);
    string getName() const;
    int getScore() const;
};

Student roster[] = {{"Ada", 88}, {"Linus", 64}, {"Grace", 92}};

sort(begin(roster), end(roster),
     [](const Student& a, const Student& b) {
         return a.getScore() > b.getScore();
     });

The const Student& parameters matter: sort makes many comparisons, and by-value parameters would copy two Student objects every time. Because the parameters are const references, getScore must be a const member function, as in 07.01.

Putting It Together: A Student Roster

#include <iostream>
#include <string>
#include <algorithm>
#include <iterator>
using namespace std;

// A student's name and course score
class Student {
private:
    string name;
    int score;

public:
    Student(string studentName, int studentScore);
    string getName() const;
    int getScore() const;
};

int main() {
    Student roster[] = {{"Ada", 88}, {"Linus", 64},
                        {"Grace", 92}, {"Alan", 55}};
    int passing = 70;

    // Highest score first
    sort(begin(roster), end(roster),
         [](const Student& a, const Student& b) {
             return a.getScore() > b.getScore();
         });

    // Count students at or above the passing score
    int passed = count_if(begin(roster), end(roster),
        [passing](const Student& student) {
            return student.getScore() >= passing;
        });

    // Find the first student below the passing score
    Student* firstFail = find_if(begin(roster), end(roster),
        [passing](const Student& student) {
            return student.getScore() < passing;
        });

    for (const Student& student : roster) {
        cout << student.getName() << ' '
             << student.getScore() << '\n';
    }
    cout << "Passed: " << passed << '\n';

    if (firstFail != end(roster)) {
        cout << "Highest failing: "
             << firstFail->getName() << '\n';
    }

    return 0;
}

Student::Student(string studentName, int studentScore)
    : name(studentName), score(studentScore) {}

string Student::getName() const {
    return name;
}

int Student::getScore() const {
    return score;
}
Grace 92
Ada 88
Linus 64
Alan 55
Passed: 2
Highest failing: Linus

Three algorithms, three lambdas, one program. Because the roster is sorted highest first, find_if’s first failing student is also the highest failing student. Ask students why the output says “Highest failing” rather than “First failing.”

Algorithm or Loop?

  • Use an algorithm when one matches the job. Its name states the intent, and it cannot go off by one.
  • Write a loop when the job does not fit a single algorithm, such as computing several results in one pass.

Students have written counting and searching loops since CISP 360. count_if is not a fancier way to do the same thing; it replaces bookkeeping code with a statement of intent.

Summary

Standard algorithms supply the loop, and a lambda supplies the question or the ordering. Captures let the same lambda adapt to local values.

Fix the Capture

What is wrong with each lambda, and how would you fix it?

// 1
int highScores = 0;
for_each(begin(scores), end(scores),
         [](int score) { if (score > 90) highScores++; });

// 2
int highScores = 0;
for_each(begin(scores), end(scores),
         [highScores](int score) mutable { if (score > 90) highScores++; });
cout << highScores << '\n';

// 3
int passing = 70;
int passed = count_if(begin(scores), end(scores),
                      [&passing](int score) { return score >= passing; });

1: Does not compile: ‘highScores’ is not captured. Fix: [&highScores].

2: Compiles but always prints 0. mutable lets the closure change its own copy; main’s highScores never moves. Fix: [&highScores] and drop mutable.

3: Nothing is broken; it prints the right count. The lambda only reads passing, so [passing] states that intent better. Include this one so students stop assuming every snippet is broken.

Desk Check: Predict the Output

Predict the output before running the program.

int values[] = {2, 4, 6};
int total = 0;
int calls = 0;

auto add = [&total, calls](int value) mutable {
    total += value;
    calls++;
};

for_each(begin(values), end(values), add);
add(5);

cout << total << ' ' << calls << '\n';

Answer: 17 0. total is captured by reference, so both the for_each copy and add itself update main’s total: 2 + 4 + 6 + 5 = 17. calls is captured by value, so every increment lands in a closure’s own copy; main’s calls stays 0.

Explain the Trace

Using the desk check code, give each value after each statement. Explain why for_each’s three calls never appear in add’s count.

Statement main’s total main’s calls for_each copy’s calls add’s calls
auto add = …
for_each(…)
add(5);
Statement main’s total main’s calls for_each copy’s calls add’s calls
auto add = … 0 0 none yet 0
for_each(…) 12 0 3, then discarded 0
add(5); 17 0 none 1

for_each received a copy of add. The copy’s reference member pointed at main’s total, so its additions reached main. Its calls member was its own value, counted to 3, and was discarded with the copy. This is 09.01’s desk check again, with a closure in place of the functor.

Debrief: Behavior Written Where It Is Used

A lambda is a functor written at the call site. Its captures decide whether it changes the caller’s data or only its own copy.

Lambda Refactor Lab

Can Lambdas Shorten This Program Without Changing It?

The roster program works. Make it shorter and clearer with standard algorithms and lambdas, without changing a single character of its output.

Slides 58–61

Have students run the original and save its output before they touch anything. The saved output is the test: any refactor that changes it is wrong, however good the code looks.

How to Run the Lab

Lab files: refactor_lab_prompt.md and roster_loops.cpp

  1. Compile and run roster_loops.cpp. Save its output with ./roster_loops > before.txt.
  2. Paste the prompt and your program into an AI assistant. Save the result as roster_lambdas.cpp.
  3. Run ./roster_lambdas > after.txt, then diff before.txt after.txt. If diff prints nothing, the outputs match.
  4. If diff shows a difference, find which job changed and fix it yourself before asking the AI again.
  5. Audit every lambda with the checklist. Fix what it flags, then run diff again.

diff compares two files line by line and prints only the lines that differ. Empty output means identical files.

Instructor answer key: assets/refactor_lab_answer_key.md. Reference solution: cpp/roster_lambdas_reference.cpp.

Audit Checklist

  • Is every capture named, rather than [=] or [&]?
  • Is each capture by value or by reference for the right reason?
  • Is each Student parameter const Student&, or Student& only when the lambda changes the student?
  • Is every find_if result checked against end before it is used?
  • Does every comparator use < or >?
  • Was any loop forced into an algorithm it does not fit?

The last question is the trap. The letter-grade tally computes five results in one pass and should stay a loop. AI tools often convert it to for_each with [&] capturing five counters, or to five count_if calls. Both pass diff, and both fail the audit.
