Arrays of Objects

An array where each element is an object

  • An array of objects uses the same bracket syntax as any other array — the element type is your class.
  • Each element gives you access to all of that object’s public methods via dot notation.

Total slides: 11 Students know arrays of structs from 15.02. This is the same pattern: Student roster[5] whether Student is a struct or a class. The new wrinkle is roster[i].method() — same two-step access, but now calling a function rather than reading a member directly.

Declaring and accessing

class Student {
public:
    string name;
    int    grade = 0;

    void   setName(string n)  { name = n; }
    void   setGrade(int g)    { grade = g; }
    string getName()  const   { return name; }
    int    getGrade() const   { return grade; }
};

int main() {
    Student roster[3];              // array of 3 Student objects

    roster[0].setName("Alice");     // [index].method()
    roster[0].setGrade(92);

    cout << roster[0].getName() << ": " << roster[0].getGrade() << "\n";
    return 0;
}

roster[0] is a Student object; roster[0].getName() calls a method on that object. The subscript selects the element; the dot selects the method. Identical pattern to arrays of structs — method calls replace direct member access.

Looping through an array of objects

const int SIZE = 4;
Student   roster[SIZE];

roster[0].setName("Alice");  roster[0].setGrade(92);
roster[1].setName("Bob");    roster[1].setGrade(85);
roster[2].setName("Carol");  roster[2].setGrade(97);
roster[3].setName("Dan");    roster[3].setGrade(78);

int best = 0;
for (int i = 1; i < SIZE; i++)
    if (roster[i].getGrade() > roster[best].getGrade()) best = i;

cout << "Top student: " << roster[best].getName()
     << " with " << roster[best].getGrade() << "\n";

Max-tracker pattern is identical to arrays of structs — just replace roster[i].grade with roster[i].getGrade(). The loop logic is unchanged; only the syntax for reading the grade differs because it’s now behind an accessor.

Upgrading Student with constructors

class Student {
private:
    string name;
    int    grade;
public:
    Student()                    { name = "Unknown"; grade = 0; }  // default
    Student(string n, int g)     { name = n; grade = g; }         // parameterized

    string getName()  const      { return name; }
    int    getGrade() const      { return grade; }
};
  • The default constructor lets Student roster[n] compile — every element needs one.
  • The parameterized constructor lets individual elements be initialized in a single expression.

This is the Student class from 16.02 applied directly to the array context. Emphasize the why: without the default constructor the array declaration fails; without the parameterized constructor the initialization list below won’t work. Both are needed.

Initializing the array at declaration

const int SIZE = 4;

Student roster[SIZE] = {
    Student("Alice", 92),
    Student("Bob",   85),
    Student("Carol", 97),
    Student("Dan",   78)
};

for (int i = 0; i < SIZE; i++)
    cout << roster[i].getName() << ": " << roster[i].getGrade() << "\n";
  • Each element in the initializer list is a constructor call — the object is fully initialized before the loop runs.
  • This replaces four pairs of setName/setGrade calls with a single compact block.

Compare this directly to the setter chain in slide 3. The array initializer list is much more readable at scale — imagine 20 students. The constructor call syntax inside the braces creates a temporary Student that is copied into each slot.

Filling from user input with constructors

const int SIZE = 4;
Student   roster[SIZE];          // default constructor fills each slot

string name;
int    grade;

for (int i = 0; i < SIZE; i++) {
    cout << "Name:  ";  cin >> name;
    cout << "Grade: ";  cin >> grade;
    roster[i] = Student(name, grade);   // construct and assign in one line
}

for (int i = 0; i < SIZE; i++)
    cout << roster[i].getName() << ": " << roster[i].getGrade() << "\n";

This pattern — declare the array with the default constructor, then overwrite each element — is the idiomatic approach when data comes from the user at runtime rather than being known at compile time. Student(name, grade) creates a fully initialized temporary; the assignment operator copies it into roster[i].

Using Print() instead of getters

class Student {
private:
    string name;
    int    grade;
public:
    Student()                { name = "Unknown"; grade = 0; }
    Student(string n, int g) { name = n; grade = g; }
    void   print() const     { cout << name << ": " << grade << "\n"; }
    string getName()  const  { return name; }
    int    getGrade() const  { return grade; }
};

int main() {
    const int SIZE = 4;
    Student roster[SIZE] = {
        Student("Alice", 92),
        Student("Bob",   85),
        Student("Carol", 97),
        Student("Dan",   78)
    };

    for (int i = 0; i < SIZE; i++)
        roster[i].print();   // one call replaces two separate getter calls
}

print() is marked const — it reads private members but doesn’t change them. This is the pattern to reach for when display logic belongs to the class rather than to main. It also hides the formatting decision inside the class: if you later want to add a label or change the separator, you change one place.

What belongs in the class?

  • Display logic belongs in the class — print() keeps output format in one place; main just calls it.
  • Comparison logic belongs in the class — an object knows its own data better than main does.
  • Collection-level operations — looping, searching, sorting — belong outside the class, where the collection lives.

Keep it simple. The goal is to plant the idea that a well-designed class does its own work. The roster loop in main is fine; the grade comparison inside that loop is a candidate for the class. Const correctness

// This compiles:
for (const Student& s : roster)
    s.print();          // print() is marked const — OK

// If print() were NOT marked const:
// error: passing 'const Student' as 'this' discards qualifiers
  • const Student& s in a range-for means “I promise not to modify this element.”
  • The compiler enforces that promise — only methods marked const are callable on a const object.
  • Marking every read-only method const is not optional style — it is what makes const references usable.

Keep it simple. Connect the dots between the const& in the range-for and the const on the method signature. One-sentence summary: “const on the method is the compiler’s way of verifying your promise.” [Option to revisit: show a mutating method called on a const reference to produce and explain the exact compiler error.]

Passing a roster to a function

void printRoster(const Student roster[], int size) {
    for (int i = 0; i < size; i++)
        roster[i].print();
}

int main() {
    const int SIZE = 4;
    Student roster[SIZE] = {
        Student("Alice", 92), Student("Bob",   85),
        Student("Carol", 97), Student("Dan",   78)
    };
    printRoster(roster, SIZE);
}
  • Functions that only read the array declare const ClassName array[], int size — the caller’s data is protected.
  • The size must travel with the array; static arrays carry no length information on their own.

Motivating slide — the point is not to teach functions in depth but to show that arrays of objects pass like any other array. The const qualifier mirrors the const& pattern from range-for. [Option to revisit: show a mutable version void sortRoster(Student roster[], int size) that modifies the array. Deferred to keep this motivating rather than comprehensive.]

Summary

  • ClassName array[n] — same syntax as any array; the class is the element type. Access: array[i].method().
  • Use constructor calls to populate an array at declaration or at runtime — no setter chains, no partially initialized state.
  • Keep display logic in print() — main should orchestrate, not compute.

Vectors of Objects

The gradebook problem

You are writing a gradebook. You know there will be students — but you do not know how many until the semester starts. A static array requires a size at compile time: too small and it crashes; too large and you waste memory. A vector<Student> starts empty and grows with every push_back, no guessing required.

Total slides: 13 This replaces the abstract “why vector beats array” intro with a concrete scenario students recognize. The decision point is: do you know the size at compile time? If yes, a static array is fine. If no, use a vector. The rest of this section shows vector replacing Student roster[SIZE] everywhere they appeared in topic 1. [Option to revisit: extend the gradebook framing to show enrollment/withdrawal (erase), late additions (push_back mid-semester), and size queries (roster.size() vs SIZE). Deferred to keep this a motivating slide.]

Declaring and adding objects

#include <vector>
using namespace std;

class Student {
public:
    string name;
    int    grade = 0;
    void   setName(string n)  { name = n; }
    void   setGrade(int g)    { grade = g; }
    string getName()  const   { return name; }
    int    getGrade() const   { return grade; }
};

int main() {
    vector<Student> roster;        // no size needed at declaration

    Student s;
    s.setName("Alice");  s.setGrade(92);  roster.push_back(s);
    s.setName("Bob");    s.setGrade(85);  roster.push_back(s);
    s.setName("Carol");  s.setGrade(97);  roster.push_back(s);

    cout << "Roster size: " << roster.size() << "\n";
    return 0;
}

Looping — index vs. range-for

// Index loop — use when you need the position
for (int i = 0; i < roster.size(); i++)
    cout << i + 1 << ". " << roster[i].getName()
         << " — " << roster[i].getGrade() << "\n";

// Range-for — use when you only need the value
for (const Student& s : roster)
    cout << s.getName() << ": " << s.getGrade() << "\n";

const Student& avoids copying the object on each iteration — important habit when objects are larger than primitives. The & is “pass by reference inside the loop”; const ensures the loop body cannot accidentally modify roster elements.

Finding the top student

// Max-tracker with a vector — same logic as with a static array
int best = 0;
for (int i = 1; i < roster.size(); i++)
    if (roster[i].getGrade() > roster[best].getGrade()) best = i;

cout << "Top student: " << roster[best].getName()
     << " with " << roster[best].getGrade() << "\n";

// Dynamic growth: read from user until "done"
string name;
while (cin >> name && name != "done") {
    int g;  cin >> g;
    Student tmp;  tmp.setName(name);  tmp.setGrade(g);
    roster.push_back(tmp);
}

The max-tracker code is identical to the static array version — only the declaration changed. The second block shows the real advantage of vector: students can enter as many records as they want without pre-allocating a size.

Upgrading Student with constructors

class Student {
private:
    string name;
    int    grade;
public:
    Student()                { name = "Unknown"; grade = 0; }
    Student(string n, int g) { name = n; grade = g; }
    void   print() const     { cout << name << ": " << grade << "\n"; }
    string getName()  const  { return name; }
    int    getGrade() const  { return grade; }
};
  • The default constructor lets vector<Student> v(n) pre-allocate elements and is required by many STL operations.
  • The parameterized constructor lets each push_back create a fully initialized object in a single expression.

Same class as topic 1 — consistency is intentional. Students should recognize that the class definition does not change based on whether it lives in an array or a vector. The container is the only thing that differs.

push_back with constructor calls

vector<Student> roster;

roster.push_back(Student("Alice", 92));
roster.push_back(Student("Bob",   85));
roster.push_back(Student("Carol", 97));
roster.push_back(Student("Dan",   78));

cout << "Roster size: " << roster.size() << "\n";   // 4
  • Each push_back receives a fully constructed temporary — no setter chain, no partially initialized state.
  • Compare to slide 2: this replaces the reused s variable and three setter calls per element.

The temporary Student created inside push_back is copy-constructed into the vector. This is the idiomatic pattern when data is known at compile time. For larger programs, emplace_back avoids the extra copy entirely — but that is a topic for CISP 400.

Dynamic input with constructors

vector<Student> roster;
string name;
int    grade;

while (cin >> name && name != "done") {
    cin >> grade;
    roster.push_back(Student(name, grade));   // construct and add in one line
}

cout << roster.size() << " students entered.\n";
  • The vector grows automatically with each push_back — no SIZE constant needed.
  • The constructor call inside push_back creates a complete object from user input without a temporary variable.

This is the cleaner version of the dynamic input loop from slide 4. The temporary Student variable tmp is gone — Student(name, grade) creates the object inline and push_back moves it into the vector. Students often find this satisfying to compare against the old approach.

Using Print() instead of getters

// Index loop with print()
for (int i = 0; i < roster.size(); i++)
    roster[i].print();

// Range-for with print() — cleaner for display
for (const Student& s : roster)
    s.print();

// Max-tracker still uses getters — Print() is for output only
int best = 0;
for (int i = 1; i < (int)roster.size(); i++)
    if (roster[i].getGrade() > roster[best].getGrade()) best = i;

roster[best].print();   // display the winner

print() and getters serve different purposes: print() is for human-readable output; getters are for logic that needs to inspect a value. The max-tracker must compare grades, so it uses getGrade(). The final display uses print(). Students should understand when each is appropriate.

What belongs in the class?

  • Display logic belongs in the class — print() keeps output format in one place; main just calls it.
  • Comparison logic belongs in the class — an object knows its own data better than main does.
  • Collection-level operations — looping, searching, sorting — belong outside the class, where the collection lives.

Keep it simple. The roster loop in main is fine; the grade comparison inside that loop is a candidate for the class. Passing a roster to a function

void printRoster(const vector<Student>& roster) {
    for (const Student& s : roster)
        s.print();
}

int main() {
    vector<Student> roster;
    roster.push_back(Student("Alice", 92));
    roster.push_back(Student("Bob",   85));
    roster.push_back(Student("Carol", 97));
    printRoster(roster);
}
  • const vector<Student>& — the function reads the vector without copying it or modifying it.
  • No size parameter needed; the vector already knows its own length via .size().

Motivating slide. The contrast with the array version (topic 1) is instructive: no size argument, no decay to a pointer, same const& protection. Worth noting: passing by value would copy every object in the vector — the & prevents that. [Option to revisit: show a mutable version void sortRoster(vector& roster) that modifies the collection. The class as a collaborator

// Before: main compares grades directly
if (roster[i].getGrade() > roster[best].getGrade()) best = i;

// After: the class does the comparison
class Student {
public:
    bool isBetterThan(const Student& other) const {
        return grade > other.grade;
    }
};

// main becomes readable
if (roster[i].isBetterThan(roster[best])) best = i;
  • isBetterThan moves the comparison rule into the class — if “better” changes, you update one method, not every loop.
  • The method is const because it reads but does not change; the parameter is const Student& for the same reason.

Same slide as topic 1 — repeated intentionally. The pattern applies equally to arrays and vectors; seeing it twice reinforces that it is a class design principle, not a container-specific trick. [Option to revisit: printAsWinner() printing “Alice wins with 97”. Also: isBetterThan with std::max_element. Both deferred for CISP 400.]

Summary

  • vector<ClassName> grows dynamically — declare it empty, add objects with .push_back().
  • Use constructor calls inside push_back to create fully initialized objects without setter chains or temporary variables.
  • Keep display logic in print() and comparison logic in methods like isBetterThan — main should orchestrate, not compute.

Key Takeaways

  • ClassName array[n] and vector<ClassName> both use [i].method() to call methods on each element
  • Use a vector when the number of objects is not known at compile time; use a static array when it is
  • const ClassName& in a range-for both prevents copying and requires const-correct methods — mark every read-only method const
  • Keep display and comparison logic in the class (print(), isBetterThan) — main should orchestrate, not compute

Appendix

Arrays of Objects: Good Practices

  • Declare the class before the array — the type must be fully defined before it can be used as an element type.
  • Use a named constant for array size (const int SIZE = 5) and use it consistently in all loops over the array.
  • Use array[i].method() — never try to access private members directly with array[i].member.

Arrays of Objects: Common Mistakes

  • Writing roster.getName()[i] instead of roster[i].getName() — the subscript comes first, then the dot.
  • Comparing getGrade() return values without understanding that the method is called on each element individually.
  • Declaring the array inside a function and expecting it to persist — static arrays on the stack are destroyed when the function returns.

Vectors of Objects: Good Practices

  • Prefer vector<ClassName> over static arrays unless the size is fixed and known at compile time.
  • Use const ClassName& in range-for loops to avoid copying objects on each iteration.
  • Call .size() instead of tracking size manually — the vector always knows how many elements it holds.

Vectors of Objects: Common Mistakes

  • Forgetting #include <vector> — vector is not available without it.
  • Modifying a vector while iterating over it with a range-for — this invalidates iterators and causes undefined behavior; use an index loop if you need to modify during iteration.
  • Using int instead of size_t (or casting) when comparing a loop counter to .size() — .size() returns an unsigned type and the comparison produces a warning.

Vectors of Objects: More Examples

// Remove a student by index (erase)

// Sort by grade using a lambda (C++11)
#include <algorithm>
sort(roster.begin(), roster.end(),
     [](const Student& a, const Student& b) {
         return a.getGrade() > b.getGrade();   // descending
     });

// Count students above 90
int count = 0;
for (const Student& s : roster)
    if (s.getGrade() >= 90) count++;
